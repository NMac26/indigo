## Scope

Portable INDIGO drivers and agents under `indigo_drivers/`, including generated drivers, hardware drivers, and agent implementations.

For the 2026-08-01 scoped baseline pass, simulator directories and SDK/vendor subtrees named `externals` or `bin_externals` were intentionally excluded. The pass covered 490 C-family source/header files in 136 remaining top-level driver and agent directories.

## Current Findings

| --- | --- | --- | --- | --- |
| DRV-001 | High | `agent_alpaca/indigo_alpaca_ccd.c:946` | `CCD_MODE` items are copied into `readoutmodes_labels` and `readoutmodes_names` by raw `property->count` index, but the arrays are only `ALPACA_MAX_ITEMS` long. The setter also accepts `value == ALPACA_MAX_ITEMS`, causing an out-of-bounds read. Clamp mode import to `ALPACA_MAX_ITEMS` and reject `value >= ALPACA_MAX_ITEMS`. | Open |
| DRV-002 | Medium | `agent_alpaca/indigo_alpaca_wheel.c:107` | Wheel slot-offset/name updates store `property->count` as `wheel.count` even though Alpaca wheel arrays are limited to `ALPACA_MAX_FILTERS`. The response paths then serialize `count` entries from fixed 32-element arrays, so a driver exposing more items can read beyond the arrays. Clamp exported count to `ALPACA_MAX_FILTERS`. | Open |
| DRV-003 | Medium | `agent_config/indigo_agent_config.c:686` | Agent configuration builds a semicolon-separated driver filter with repeated `strcat()` into one `INDIGO_VALUE_SIZE` text item. A server exposing enough selected drivers can overflow the filter string. Build with remaining-capacity checks or truncate safely. | Open |
| DRV-004 | Medium | `agent_imager/indigo_agent_imager.c:3485` | The imager agent mirrors wheel slot names by assigning `AGENT_WHEEL_FILTER_PROPERTY->count = property->count`, but the property was initialized with `FILTER_SLOT_COUNT` items. A wheel with more than 24 slots can write past the property items when copying labels. Clamp to `FILTER_SLOT_COUNT` or resize the property before copying. | Open |
| DRV-005 | Medium | `agent_alpaca/indigo_alpaca_switch.c:564` | Alpaca switch-name handling copies `AUX_OUTLET_NAMES` and `AUX_SENSOR_NAMES` with raw `property->count` into fixed `5 * ALPACA_MAX_SWITCHES` storage. The value paths clamp each bank to 8 items, but the name paths do not, so a property with too many names can write past the selected bank. Clamp each name bank to `ALPACA_MAX_SWITCHES`. | Open |
| DRV-006 | Medium | `agent_alpaca/indigo_agent_alpaca.c:670` | `INFO_DEVICE_NAME` text is copied with `strcpy()` into `device_name[INDIGO_NAME_SIZE]`, while INDIGO text values are `INDIGO_VALUE_SIZE`. A long device-name text item can overflow the Alpaca device-name cache. Use `INDIGO_COPY_NAME()` or another bounded copy. | Open |
| DRV-007 | Medium | `dome_nexdome3/indigo_dome_nexdome3.c:1203` | The optional NexDome custom command path formats `NEXDOME_COMMAND_ITEM->text.value` into `char command[NEXDOME_CMD_LEN]` with `sprintf()`. The text value can be much larger than the 100-byte command buffer, so a long custom command overflows the stack buffer. Use `snprintf()` and reject/truncate oversized commands. | Open |
| DRV-008 | Medium | `focuser_steeldrive2/indigo_focuser_steeldrive2.c:642` | SteelDrive2 formats the user-editable `X_NAME` text item into `char command[64]` with `sprintf("$BS SET NAME:%s", ...)`. `X_NAME_ITEM->text.value` is an INDIGO text value, so a long name can overflow the command buffer before it is sent. Bound the accepted name length or use `snprintf()` with state feedback on truncation. | Open |
| DRV-009 | Medium | `dome_nexdome3/indigo_dome_nexdome3.c:567` | NexDome3 parses incoming `XB->...` messages with `sscanf(message, "XB->%s", state)` into `char state[20]`. A malformed or unexpectedly long controller message can overflow the stack buffer before the value is copied to the INDIGO text item. Add a field width or parse with bounded copying. | Open |
| DRV-010 | Medium | `system_ascol/libascol/libascol.c:405` | `ascol_parse_devname()` parses `DEVICE_PORT_ITEM->text.value` with unbounded `%s` into the caller's `host` buffer; the system driver passes `char host[255]`, while the INDIGO text value can be larger. A long `tcp://...` or `ascol://...` value can overflow `host`. Use width-limited parsing or pass the destination size. | Open |
| DRV-011 | Medium | `agent_astrometry/indigo_agent_astrometry.c:205` | The Astrometry agent builds `buffer[8192]` with `vsnprintf()` and then appends `" 2>&1"` into another 8192-byte buffer with `sprintf()`. A command truncated to the full source buffer can overflow `command_buf`; the same file also parses `Field size` units into `char s[16]` with unbounded `%s`. Use a single bounded `snprintf()` and width-limited parsing. | Open |
| DRV-012 | Medium | `agent_astap/indigo_agent_astap.c:331` | The ASTAP agent has the same equal-sized `buffer` to `command_buf` append overflow as Astrometry. It also builds index parameters and index paths with repeated `sprintf()` into 512-byte buffers using `base_dir`, which can be near the buffer limit. Convert command, parameter, and path construction to checked `snprintf()` with remaining-capacity tracking. | Open |
| DRV-013 | Medium | `gps_gpsd/indigo_gps_gpsd.c:59` | `gpsd_open()` copies the editable device-port text into `host_name[INDIGO_NAME_SIZE]` and `port[15]` with `strcpy()`/`strncpy()` without checking host or port length. A long `gpsd://...` value can overflow the host or port buffer before `gps_open()`. Parse with bounded lengths and reject invalid endpoints. | Open |
| DRV-014 | Medium | `mount_synscan/indigo_mount_synscan_driver.c:1013` | `synscan_save_position()` writes the HOME-based `.indigo` path with `snprintf()` but then appends the park filename using `sprintf(buffer + path_end, ...)`. If HOME is long enough for `snprintf()` to truncate, `path_end` is the would-have-written length and can point past `buffer`. Compose the complete path with one checked `snprintf()`. | Open |
| DRV-015 | Medium | `ccd_ptp/indigo_ptp.c:1533` | PTP string switch values are decoded into `PTP_MAX_CHARS` 256-byte entries, but refreshed property names are copied into `char str[INDIGO_NAME_SIZE]` with `strcpy()`. A camera-provided string value longer than 127 bytes can overflow `str` before the item name is updated. Use bounded copying and define a deterministic truncation or rejection policy for item names. Note (2026-08-01): the Olympus per-second `ChangedProperties` refresh loop (`indigo_ptp_olympus.c:388`) routes camera descriptors through this path continuously. | Open |
| DRV-016 | Medium | `ccd_ptp/indigo_ptp_olympus.c:306` | The Olympus ObjectAdded dedup path calls `GetObjectInfo` with a discarded response size, then decodes fixed offsets (`+8`, `+40`, string up to 511 bytes) with no length or NULL check. On the ICA transport the buffer is `malloc`ed at exactly the reported length, so a payload shorter than ~563 bytes causes a heap overread; on libusb a success with no data phase leaves `buffer == NULL` and dereferences it. `ptp_decode_string()` also never NUL-terminates, so `filename` can be compared/copied unterminated. Request and validate the size before decoding and terminate the filename. (Mirrors the pre-existing generic pattern at `indigo_ptp.c:1701`.) | Open |
| DRV-017 | Low | `ccd_ptp/indigo_ptp_olympus.c:306` | In the same dedup path, `free(buffer)` sits only inside the transaction-success branch; both transports can allocate `*data_in` and still return `false` (ICA returns `code == OK` after the copy, libusb can fail reading the response container). A camera answering data plus a non-OK response leaks one buffer per ObjectAdded event in a long-running event loop. Free the buffer on the failure path too. | Open |
| DRV-018 | Medium | `ccd_ptp/indigo_ptp_olympus.c:488` | `ptp_olympus_exposure()` keys success on `PRIVATE_DATA->image_added`, but the generic handler (`indigo_ptp.c:1736`) sets that flag unconditionally per object, even when the `GetObject` download fails. A failed download makes the exposure return success and leaves `CCD_IMAGE` BUSY forever; in RAW+JPEG mode the first (preview) object ends the wait before the RAW arrives, and an unsynchronized reset at line 469 can attribute exposure N's late frame to exposure N+1. Make the flag per-capture and condition it on successful processing. | Open |
| DRV-019 | Medium | `ccd_ptp/indigo_ptp_olympus.c:347` | On the libusb build the Olympus event pump reads at most one interrupt-endpoint event per 1 s timer tick (`indigo_reschedule_timer(device, 1, ...)`), unlike the generic continuous pump. Multi-slot RAW+JPEG shots emit ~6 events each, so bursts back up in the camera queue, image delivery lags, and the 60 s wait in `ptp_olympus_exposure()` can expire with a false ALERT. Latent on Linux — hardware verification covered only the ICA path, which drains the queue. Drain until empty per tick or reschedule at 0. | Open |
| DRV-020 | Medium | `ccd_ptp/indigo_ptp.c:1062` | The ICA (macOS) `ptp_transaction()` performs no `usb_mutex` serialization, unlike the libusb variant, and all in-flight requests share one delegate semaphore and response/input slot. The Olympus combination of a 50 ms liveview loop plus the 1 Hz `ChangedProperties` poll runs transactions from two threads concurrently, so responses can be cross-attributed (a liveview JPEG parsed as a property dump). Pre-existing core gap (Fuji polls similarly) but heavily exercised by this branch. Serialize ICA transactions. | Open |
| DRV-021 | High | `ccd_ptp/indigo_ptp.c:761` | Enum-form property descriptors decode a raw camera-provided `uint16` count (up to 65535) into `target->count` and then write `value.sw.values[i]` for every `i`, but `values` is `int64_t[PTP_MAX_ELEMENTS]` (1024). A descriptor claiming more than 1024 enum values causes out-of-bounds 8-byte writes across the `properties[]` array and beyond. Pre-existing core defect found while tracing the Olympus refresh loop, which feeds camera descriptors through this decode every second. Clamp `count` to `PTP_MAX_ELEMENTS`. | Open |
| DRV-022 | Low | `ccd_ptp/indigo_ptp_olympus.c:313` | Duplicate-copy detection compares only the single most recent object name/size, so it only catches duplicates that arrive consecutively. RAW+JPEG saved to two cards with slot-major event ordering re-downloads (and re-delivers) the second copy of each object. Track recent objects per capture instead of one entry. | Open |
| DRV-023 | Low | `ccd_ptp/indigo_ptp_olympus.c:421` | `ptp_olympus_initialise()` decodes the `GetStorageIDs` count without checking `buffer` or `size`: a success with no data phase on libusb leaves `buffer == NULL` and crashes in `ptp_decode_uint32()` at connect; on ICA a payload under 4 bytes overreads an exact-size allocation. Guard with `buffer && size >= sizeof(uint32_t)` as the ChangedProperties path already does. | Open |
| DRV-024 | Low | `ccd_ptp/indigo_ptp_olympus.c:445` | The `ExposureProgramMode` injection walks `info_properties_supported[]` (1024 entries) to the terminator and writes at `[last]` with no bound check, and passes a possibly-NULL descriptor buffer to `ptp_decode_property()`. A device advertising 1023 surviving properties overwrites the final terminator, after which every terminator-scan loop walks past the array. Same pattern exists in `indigo_ptp_fuji.c:459`. Bound the append and check the buffer. | Open |
| DRV-025 | Low | `ccd_ptp/indigo_ptp_olympus.c:439` | The connect path calls `ptp_get_event()`, which on libusb blocks on the interrupt endpoint for the full 10 s `PTP_TIMEOUT` while holding `usb_mutex` and then issues `libusb_clear_halt()` on a non-halted endpoint. If the CameraControlMode write produced no event, every Linux connect stalls ~10 s inside `ptp_olympus_initialise()`. Use a short timeout or make the drain optional. | Open |
| DRV-026 | Low | `ccd_ptp/indigo_ptp_olympus.c:416` | `olympus_private_data` is allocated on every connect but only freed on physical unplug (`indigo_ccd_ptp.c:761`, `:809`); the soft-disconnect path never frees `vendor_private_data`, leaking ~272 bytes per connect/disconnect cycle. ## Review Focus

- Driver lifecycle: `INDIGO_DRIVER_INIT`, `INDIGO_DRIVER_SHUTDOWN`, and `INDIGO_DRIVER_INFO`.
- Attach/detach ordering and resource cleanup.
- Connection/disconnection behavior and property visibility.
- Property state transitions, especially `BUSY -> OK` and `BUSY -> ALERT`.
- Handler queue, timer, and async usage.
- Generated driver source synchronization with `.driver` inputs.
- Simulator coverage under `indigo_test/integration/`.
